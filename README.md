# 모아 스도쿠

GitHub Pages에서 실행할 수 있는 한국어 스도쿠 게임입니다. HTML, CSS, JavaScript만 사용하며 계정과 빌드 과정이 필요하지 않습니다. 페이지는 정적 파일로 배포하고, 멀티 플레이 연결 중개에는 공개 PeerJS 서비스를 사용합니다.

- 시작 화면, 싱글 플레이, 방 번호로 연결하는 2인 멀티 플레이
- 쉬움 / 보통 / 어려움: 빈칸 개수 기준의 난이도
- 매번 새 퍼즐 생성, 해가 하나인지 확인
- 숫자 입력, 후보 메모, 지우기, 되돌리기, 힌트 3회
- 틀린 숫자 표시, 타이머, 일시 정지, 완성 알림
- 브라우저 자동 저장 및 이어하기 (같은 브라우저·주소에서 유지)
- 모바일과 키보드 지원

## GitHub Pages 배포

이 파일들을 GitHub 저장소에 올리고 **Settings → Pages → Build and deployment → Deploy from a branch**를 선택합니다. 배포할 브랜치의 **/(root)** 를 지정하고 저장하면 됩니다. 모든 파일은 상대 경로를 사용하므로 `https://사용자.github.io/저장소/`에서도 동작합니다.

## 멀티 플레이

1. 두 사람이 같은 페이지를 엽니다.
2. 한 사람이 **멀티 플레이 → 방 만들기**를 누르고 생성된 여섯 자리 방 번호를 알려줍니다.
3. 다른 사람이 **멀티 플레이 → 방 참가하기**에서 번호를 입력합니다.
4. 연결되면 같은 쉬움 퍼즐로 바로 시작합니다. 각자 풀고, 먼저 정확히 완성한 사람이 승리합니다. 상대의 진행 상황도 표시됩니다.

대전 중 힌트와 일시 정지는 사용할 수 없습니다. 방장이 처음 확인한 올바른 완성 입력으로 승패를 한 번만 결정하므로, 매우 근소한 차이는 통신 지연에 영향을 받습니다. 승자와 패자에게 각각 결과 화면을 보여줍니다. 싱글 플레이 저장은 유지됩니다.

**GitHub Pages 호환:** 모든 프로그램과 라이브러리는 저장소에 포함됩니다. 서버 코드, API 키, 데이터베이스, 별도 백엔드 배포가 필요하지 않습니다. 연결 중개는 [PeerJS Cloud](https://peerjs.com/client/getting-started)의 공개 신호 서버, 게임 데이터 전송은 WebRTC를 사용합니다. PeerJS 1.5.5의 MIT 라이선스는 `vendor/peerjs.LICENSE`에 포함했습니다.

멀티 플레이는 인터넷과 WebRTC를 지원하는 최신 브라우저가 필요합니다. 공개 연결 서비스의 가용성이나 네트워크 방화벽/NAT에 따라 접속이 제한될 수 있습니다. PeerJS 라이브러리의 기본 STUN/TURN 설정을 사용합니다. 제한된 네트워크에서 연결되지 않으면 다른 Wi-Fi나 모바일 네트워크를 시도하세요. 두 사람은 대전 화면을 열어두어야 하며, 새로고침·방 나가기·연결 끊김 시 대전은 무효로 종료됩니다. 대전과 방 번호는 영구 저장되지 않으며, 친구끼리 즐기는 대전용으로 서버 기반 부정행위 방지 기능은 없습니다.

## 로컬 실행

`index.html`을 브라우저로 직접 열면 바로 플레이할 수 있습니다. 일반 스크립트를 사용하므로 로컬 파일에서도 게임이 실행됩니다. 또는 간단한 HTTP 서버를 사용할 수 있습니다.

```sh
python3 -m http.server 8000
```

브라우저에서 `http://localhost:8000`으로 접속합니다. 외부 폰트를 불러오지 못해도 기본 글꼴로 게임을 이용할 수 있습니다.

## 검증

Node.js가 있으면 퍼즐 생성 및 멀티 플레이 프로토콜 검증을 실행할 수 있습니다.

```sh
node --test tests/*.test.mjs
```
